Ctrl+V for text and image paste

Can Herdr, Claude Code, or Pi take Ctrl+V directly, so the Alt+V dispatcher is not necessary?

No. Only the outer terminal (Kitty or Emacs Ghostel) can read the local clipboard and choose text paste or image key. Herdr's paste key works only for images and only in herdr --remote. Keep the dispatcher.

App in pane

Claude Code · Pi · zsh

Reads the clipboard of the host where it runs.

Clipboard has text only

  1. Dispatcher does a normal paste (paste_from_clipboard / ghostel-yank).
  2. Herdr forwards the bracketed paste, local or remote.
  3. Any app gets the text.

Clipboard has an image

  1. Dispatcher sends Alt+V.
  2. Local: Herdr forwards Alt+V; Claude Code / Pi read the Mac clipboard.
  3. Remote: Herdr drops Alt+V, copies the image to a remote temp file, and pastes its path.
  4. zsh: Alt+V is undefined-key, so nothing happens.

2. Why the other layers cannot decide

Herdr

  • One paste key: keys.remote_image_paste (default ctrl+v, yours alt+v).
  • Remote only. Image only. With no image, it sends the raw key. It never pastes text.
herdr v0.9.5 src/client/clipboard_images.rs#L71-L73, src/client/mod.rs#L990-L1007

Claude Code & Pi

  • Both default to Ctrl+V for images on macOS.
  • Pi falls back to text. Claude Code: no text fallback is documented (not confirmed).
  • Remote: they cannot see the Mac clipboard.
code.claude.com/docs/en/keybindings · pi interactive-mode.js:2436-2491

Kitty plain paste

  • Sends text only. An image-only clipboard sends nothing.
  • So Herdr's empty-paste trigger cannot fire.
kitty v0.49.2 kitty/boss.py#L3001-L3008

Karabiner

  • If you remove Kitty and Emacs from the rule, Ctrl+V reaches the terminal, but someone must still choose text or image.
  • In Emacs outside Ghostel, C-v scrolls instead of paste.
.config/karabiner/karabiner.json:202-231
